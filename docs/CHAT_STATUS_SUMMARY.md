# 채팅 기능 현황 요약

> 작성일: 2026-06-24
> `docs/` 내 채팅 관련 문서(`chat-impl/`, `chat-trouble-shoot/`, `trouble-impl/`, `CHAT_*.md`)를 전부 종합해 "지금 뭐가 해결됐고, 뭐가 보류/대기 중이고, 뭐가 백엔드 작업 대기인지"만 추린 요약본. 근거·코드 위치는 각 링크된 원본 문서에 있다.

## 1. 한눈에 보기

| 상태                | 의미                                                             |
| ------------------- | ---------------------------------------------------------------- |
| ✅ 해결됨           | 백엔드 수정 완료 (일부는 부분 검증, 일부는 코드 diff 확인까지만) |
| 🟡 결정/검증 대기   | 코드는 있지만 기획 결정 또는 실기기 재검증이 더 필요함           |
| 🔴 백엔드 작업 대기 | 백엔드가 손대야 하는 항목, 프론트는 대응 불가                    |
| ⚠️ 미착수 버그      | 발견은 됐지만 아직 고치지 않음(우선순위 미배정)                  |

채팅 API 연동(이슈 #21) 본 작업 11건은 전부 완료됐고, 이후 실기기 테스트에서 나온 문제들을 백엔드와 주고받으며 정리하는 단계다.

## 2. ✅ 해결됨

| 항목                                                                                                     | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SSE nginx 버퍼링                                                                                         | `X-Accel-Buffering: no` 헤더 추가(PR #173, `ae64c33`)로 수정. 사용자가 실기기에서 점진적 스트리밍을 직접 관찰함(비공식 신호) — 진단 로그 기반 정식 재검증은 아직 안 함(§3-1)                                                                                                                                                                                                                                                                                                                                                                                        |
| BUFFER 모드 위기 재분류 시 severity 항상 1 고정                                                          | 원본 메시지를 실제로 전달하도록 수정(`f0c6744`) → severity 2/3(핫라인 포함) 가능해짐                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| CAUTIOUS_SPECULATIVE 위기 재분류 시 `crisis` 이벤트 누락                                                 | BUFFER와 동일하게 `crisisFlowService.handle()` 호출하도록 수정(`f0c6744`). 프론트 fallback 안전망(`handleCrisisFallback`)은 이론상 도달 불가능해짐 — 코드는 그대로 두고 OPEN_ISSUES만 갱신                                                                                                                                                                                                                                                                                                                                                                          |
| `is_socratic` 필드 추가                                                                                  | `done` 이벤트에 신규 필드, 프론트 타입에도 반영(커밋 `c18bda3`). **실연동은 아직** (§3-3 참고)                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `emotion_score_ai` 항상 null 버그                                                                        | `ExtractorLLM`에 산출 항목 추가해 수정(`4000fb9`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| PolicyEngine 순위4/5 모순 의심                                                                           | 확인 결과 버그 아님 — 서로 다른 신호(전체 카테고리 vs self-harm 한정)라 의도된 설계                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 문서 동기화                                                                                              | `SSE_SPEC.md`/`API_SPEC.md`/`CHAT_SESSION_FLOW.md`를 위 수정사항 기준으로 갱신 완료                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 빈 AI 말풍선 잔존 (프론트 버그)                                                                          | `delta` 없이 곧장 `crisis`로 끝나는 경로에서 `session_meta` placeholder가 안 채워진 채 남던 문제. `chatStore`에 `replaceMessageAsCrisis` 추가해 placeholder를 위기 말풍선으로 전환하도록 수정                                                                                                                                                                                                                                                                                                                                                                       |
| AI 캐릭터가 항상 "미오"로 고정 (프론트 버그)                                                             | `SessionStart.tsx`가 `chatStore.characterId` 기본값(`'mio'`) 대신 `useSelectedCharacterId()`(머지 커밋 `c973379`가 앱 전역에 도입한 패턴)를 쓰도록 수정 — 화면 표시와 `startSession()` 요청 바디 둘 다 올바른 캐릭터를 씀. 분석/계획: [chat-trouble-shoot/01-character-id-not-synced.md](./chat-trouble-shoot/01-character-id-not-synced.md). 코드 수정 완료, 시뮬레이터 부재로 실기기 검증은 아직 안 함                                                                                                                                                            |
| 세션 종료 후 요약→결과→홈 전환 뒤로가기/리셋 타이밍 버그 (프론트 버그)                                   | 결과 화면에서 홈으로 이동 후 채팅 탭 재진입 시 빈 화면, 요약/결과 화면에서 뒤로가기 시 빈 화면. `useEndChatSession`의 `router.replace`를 `push`로 롤백(`SessionEnd`의 `dismissAll()` → `index` 복귀 전제 복원) + `SessionSummary`/`SessionEnd`에 `usePreventRemove`/`gestureEnabled: false`로 뒤로가기 자체를 차단. 분석/계획: [chat-trouble-shoot/06-session-end-flow-back-navigation.md](./chat-trouble-shoot/06-session-end-flow-back-navigation.md). 뒤로가기 차단은 실기기에서 동작 확인됨, 나머지 시나리오는 검증 대기                                        |
| 요약 화면 로딩 중 reload 후 채팅 탭 재진입 시 검은 화면 (프론트 버그)                                    | `SessionSummary.tsx`가 `sessionId` 없이 마운트되면 배경도 없이 `return null`하던 문제. 스타일된 fallback + `/(main)/chat`로 자가복구 redirect 추가, `usePreventRemove`는 `sessionId`가 있을 때만 켜지도록 조건부로 변경, 루트 `_layout.tsx`에 `expo-router` 기본 `ErrorBoundary` 추가(에러 바운더리 부재 안전망). 분석/계획: [chat-trouble-shoot/07-chat-summary-black-screen-after-reload.md](./chat-trouble-shoot/07-chat-summary-black-screen-after-reload.md). 코드 수정 완료, 시뮬레이터 부재로 실기기 검증은 아직 안 함                                       |
| 결과 화면("홈으로 돌아가기") 이후 채팅 탭이 결과 화면에 고착되어 새 대화 시작 불가 (프론트 버그, 치명적) | `SessionEnd`/`SessionSummary`의 `usePreventRemove(true/!!sessionId, () => {})`가 액션 타입을 가리지 않고 무조건 차단해 정리용 `dismissAll()`(`POP_TO_TOP`)까지 막던 문제. `usePreventRemove`를 제거하고 `navigation.addListener('beforeRemove', ...)`로 직접 구독해 `POP`/`GO_BACK`(실제 뒤로가기)만 막고 `POP_TO_TOP`(`dismissAll()`)은 통과시키도록 수정. 분석/계획: [chat-trouble-shoot/09-dismissall-blocked-by-prevent-remove.md](./chat-trouble-shoot/09-dismissall-blocked-by-prevent-remove.md). 코드 수정 완료, 시뮬레이터 부재로 실기기 검증은 아직 안 함 |

## 3. 🟡 결정/검증 대기

| #   | 항목                                                    | 현황                                                                                                                                                                                                                                                                          |
| --- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | SSE 스트리밍 정식 재검증                                | 진단 로그(`useChatSse.ts`의 `★` 표시 5곳) 기반 재현 캡처 미완료. 실기기 QA가 선행조건이라 보류 중, 통과하면 로그 제거                                                                                                                                                         |
| 2   | 감정 점수 제출 흐름 재설계                              | 백엔드가 `POST /v1/sessions/{id}/emotion-score`를 **세션 단위 + 세션 종료 후에만** 호출 가능하게 구현해, 현재 "소크라테스 답변 직후 슬라이더" UX와 안 맞음. A(제출 시점만 미루기)/B(요약 화면에서 보정, 권장) 중 기획 결정 필요                                               |
| 3   | `is_socratic` 실연동                                    | 백엔드 판정이 "물음표 포함 여부"라 오탐 위험 커서 연동 보류(A안) 권장했었으나, 백엔드가 판정 로직을 다시 고치기로 확인(2026-06-24)되어 연동 진행으로 결정 변경. 구체적 수정 내용 미확정 — 배포 후 진행 ([상세 계획](./chat-trouble-shoot/04-socratic-emotion-slider-plan.md)) |
| 4   | [OPEN_ISSUES.md](./chat-impl/OPEN_ISSUES.md) 나머지 4건 | `summary_status` done→viewed 전환 시점 불명 / `bias_types_detected` 포맷 / 위기 후 안내 배너 여부 / 메시지 전송 실패 재전송 버튼. 전부 안전한 임시 처리로 구현이 막혀있진 않음                                                                                                |

## 4. 🔴 백엔드 작업 대기 (프론트 대응 불가)

| #   | 항목                              | 현황                                                                                                                                                |
| --- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `key_thoughts` / `socratic_count` | DB 컬럼·DTO 필드만 추가됐고 채우는 로직이 없어 **항상 null**. 채워지기 전까지 관련 UI 작업 불가                                                     |
| 2   | `emotion_score_ai` 조회 경로      | POST 응답에만 포함, 별도 GET 경로 없음 — 사용자가 점수를 제출하지 않으면 조회 불가                                                                  |
| 3   | `messages.is_crisis_flagged`      | ASSISTANT 행에만 반영, USER 행은 항상 `false`. 현재 프론트가 이 컬럼을 직접 쓰는 곳은 없어 당장 영향 없음                                           |
| 4   | PolicyEngine 순위9 도달 가능성    | `repetitiveNegative`/`emotionSpike` 단독 신호 분기가 여전히 사실상 도달 불가능할 가능성 — 재확인 요청했으나 답 없음. 순수 백엔드 로직, FE 영향 없음 |
